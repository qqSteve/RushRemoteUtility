# RushRemoteUtility 1.1 для Windows x64

## Один раз перед первой сборкой с обновлениями

1. В PowerShell из папки проекта выполните:

       powershell -NoProfile -ExecutionPolicy Bypass -File .\rush-release\setup-key.ps1

   Скрипт использует OpenSSL из Git for Windows. Он печатает публичный RUSH_UPDATE_PIN и путь к закрытому файлу signing.pem в профиле пользователя. Повторный запуск использует тот же ключ. Сохраните резервную копию в защищённом месте. Не добавляйте signing.pem в репозиторий и не отправляйте его в чат.
2. В GitHub откройте Settings → Secrets and variables → Actions. На вкладке Secrets создайте RUSH_SIGNING_KEY. Значение — весь текст signing.pem со строками BEGIN и END. На вкладке Variables создайте:

   | Name | Value |
   |---|---|
   | RUSH_UPDATE_PIN | Только публичная строка Base64 из вывода скрипта |
   | RUSH_SERVER | Адрес вашего VPS, сейчас 178.22.24.232 |
   | RUSH_PUBLIC_KEY | Публичный ключ вашего RustDesk-сервера из id_ed25519.pub |

   Ключи обновлений и удалённого доступа выполняют разные задачи. Для автоматического скачивания с GitHub релизы должны быть публично доступны. Адрес публичного репозитория подставится автоматически. Компьютерам не нужны токены GitHub. Смена ключа подписи потребует ручного обновления уже установленных клиентов.
3. Создайте обычный GitHub Release с новым тегом v1.1.0 из коммита с этими изменениями. Если такой тег уже опубликован, выберите больший свободный номер. Используйте формат vX.Y.Z. Задание Windows Actions соберёт и приложит к релизу RushRemoteUtility.exe, windows-x64.zip и стабильный подписанный манифест stable.bin. Сборка требует минут GitHub Actions. Новая версия должна быть обозначена GitHub как Latest. До появления всех трёх файлов канал может временно отвечать 404.
4. Один раз запустите новый EXE вручную на тестовом ПК и установите его как службу в стандартную папку Program Files\RushRemoteUtility. Более ранняя сборка ещё не умеет обновляться самостоятельно.
5. Для проверки выпустите следующий стабильный тег, например v1.1.1. Сначала проверьте одного клиента. В открытом сеансе установка должна отложиться. Закройте сеанс и нажмите «Проверить обновления». После установки проверьте актуальную версию через «Диагностика», прежние ID, постоянный пароль и повторный вход с iPhone. Затем устанавливайте на остальных ПК.

Ручной запуск Actions без ключей позволяет проверить интерфейс. Такой EXE сообщит, что канал не настроен. Чтобы включить обновления, потребуется новая сборка с публичным ключом. Номер ручной сборки берётся из rush-release/VERSION, при сборке релиза используется тег.

## На компьютере

- «Мои компьютеры» — локальные избранные устройства с названиями. Сохраните ID и имя, нажмите на строку для подключения. Для изменения имени сохраните тот же ID ещё раз. Кнопка удаления убирает устройство из избранного.
- «Диагностика» — версия, служба, статус регистрации, наличие ключа, TCP-соединение с ID-сервером и ретранслятором. В отчёте нет паролей или значения ключа. TCP-тест не устанавливает сеанс и не проверяет UDP.
- «Подготовить ПК» показывает состояние службы и режима доступа. Установите клиент при необходимости, через штатные настройки безопасности задайте постоянный пароль и выберите подтверждение по паролю. Откройте мастер повторно, чтобы проверить результат. Имя ПК и ID можно скопировать одной кнопкой.
- «Проверить обновления» запускает проверку вручную. Автопроверка выполняется при работе установленной службы после запуска и затем раз в сутки. Переключатель автообновлений находится в общих настройках. Служба проверяет подпись Ed25519, SHA-256, размер пакета и номер версии. Установка откладывается при активных сеансах. Запланированная задача Windows запускает службу после замены файлов программы и пробует вернуть предыдущую папку при сбое. Рабочая папка — Program Files\RushRemoteUtility Maintenance. В status.txt находится последнее сообщение. Профили пользователя и службы не входят в пакет обновлений.

## Если релизы закрыты

Можно разместить канал на собственном HTTPS-сервере. До первой сборки задайте RUSH_UPDATE_URL (например https://updates.example.com). В каталоге статики /srv/rush-updates будут stable.bin и vX.Y.Z/windows-x64.zip. Для автоматической выкладки настройте SSH-аккаунт с правом записи в этот каталог, переменные RUSH_DEPLOY_HOST, RUSH_DEPLOY_USER, RUSH_DEPLOY_KNOWN_HOSTS (проверенная строка known_hosts) и секрет RUSH_DEPLOY_KEY. Для этого варианта на VPS требуется python3 и уже работающий HTTPS с доверенным сертификатом. При публичном GitHub этот раздел можно пропустить.
